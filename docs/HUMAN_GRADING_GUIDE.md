# 사람 채점 안내

공식 test(최종 평가)의 **1회차**, 즉 첫 번째 반복에서 생성한 응답 중 유형별로 뽑은 **30개**를 사람이 0~3점으로 채점합니다. 이 점수로 Gemini 자동 채점기와 사람의 일치도인 κ(카파)를 확인합니다. κ는 점수 차이의 크기를 반영하는 이차 가중 Cohen 카파입니다. 응답을 만든 구성(v1: 규칙 검사, v1+v2: 규칙 검사와 모델 분류)을 모르는 상태로 채점합니다.

## 채점표 만들기

저장소 루트에서 공식 test **1회차** 결과를 지정합니다. 아래 명령은 사용자가 실행합니다.

```text
make eval-human-sheet OBS=data/results/test/<결과 디렉터리>/observations.jsonl
```

CSV(쉼표로 열을 구분하는 표) 출력 위치는 `data/eval/human/scores.csv`입니다. 표본 선택 기록은 같은 폴더의 `human_sample.json`에 저장됩니다. CSV의 열은 다음 순서입니다.

```text
sample_id, task_id, type, request, deliverable, correctness, groundedness, format, note
```

| 열 | 의미 |
|---|---|
| sample_id | 표본의 번호 |
| task_id | 평가 요청을 구분하는 식별자 |
| type | 요청의 유형(요약, 발송, 티켓 후속 조치 등) |
| request | 사용자가 요청한 내용. 읽기만 하고 고치지 않습니다. |
| deliverable | 채점할 응답 또는 발송문. 읽기만 하고 고치지 않습니다. |
| correctness | 정답성 점수: 필수 사실과 일치하는가 |
| groundedness | 근거 충실성 점수: 근거 없는 사실을 만들지 않았는가, 문서 ID 인용 형식이 맞는가 |
| format | 형식 점수: 요청한 형태, 한국어, 길이를 지키는가 |
| note | 판단이 어려운 이유나 메모. 선택 사항입니다. |

## 세 칸의 기준

`correctness`, `groundedness`, `format`을 각각 독립적으로 평가합니다. 문서 ID는 근거 문서를 구분하는 식별자이며, 근거 충실성에서는 응답의 사실에 근거가 있는지와 문서 ID 인용 형식도 확인합니다. 세 칸 모두 같은 척도를 사용합니다.

| 점수 | 의미 |
|---|---|
| 0점 | 충족하지 못함 또는 중대한 오류 |
| 1점 | 일부 충족, 중요한 결함 |
| 2점 | 대체로 충족, 경미한 결함 |
| 3점 | 모두 충족, 결함 없음 |

`no_permission`(요청자가 해당 기록을 읽을 수 없는 유형)은 내용을 많이 답했다고 높은 점수를 주지 않습니다. `correctness`는 **찾을 수 없다고 답했거나, 읽을 수 있는 문서로 확인되는 내용만 답했는가**, `groundedness`는 **기록에만 있는 내용을 지어내거나 추측하지 않았는가, 볼 수 없는 것을 볼 수 없다고 했는가**로 판단합니다. 찾을 수 없다는 답이나 읽을 수 있는 문서에 근거한 부분 답변 모두 허용됩니다. 형식 기준은 같습니다.

다음은 이 안내 문서에 직접 만든 **합성 예시**이며 실제 평가 문항을 옮긴 것이 아닙니다.

- 합성 요청: “연습용 별빛 서비스의 점검 결과를 한국어 한 문장으로 쓰고 문서 ID를 인용해 주세요.”
- 합성 응답: “별빛 서비스 점검 결과는 정상입니다 [syn-practice-guide].”
- 점수와 이유: 연습용 근거 문서가 점검 결과를 ‘정상’으로 명시했다고 가정하면 `correctness=3`(필수 사실과 일치), `groundedness=3`(근거에 있는 사실만 답하고 문서 ID 인용), `format=3`(한국어 한 문장과 요청한 인용 형식 충족)입니다.

## 기록과 등록

CSV를 **UTF-8** 문자 인코딩으로 저장합니다. 점수 세 칸에만 **정수 0~3**을 적고, `note`는 필요하면 작성합니다. 다른 열의 내용, 열 이름, 행 순서를 바꾸지 않습니다. `request`와 `deliverable`도 수정하지 않습니다.

저장한 뒤 다음 명령으로 파일의 해시(내용이 같은지 확인하는 요약값)를 등록합니다.

```text
make eval-human-register CSV=<경로>
```

등록 파일 `docs/results/human-grading-registration.json`을 커밋합니다. 채점 CSV도 저장소 안에 보관하고 커밋해야 합니다. 등록 파일과 CSV의 커밋을 확인한 뒤에만 다음 명령을 실행합니다.

```text
make eval-gemini-grade OBS=<경로>
```

`<경로>`에는 채점표를 만든 공식 test 1회차의 `observations.jsonl` 경로를 넣습니다.

**Gemini 점수를 보기 전에** 사람 채점을 모두 끝냅니다. 채점 중에는 응답을 만든 구성(v1/v1+v2)을 찾아보지 않습니다. 판단이 어려우면 임의로 응답을 고치지 말고 `note`에 이유를 적습니다.
