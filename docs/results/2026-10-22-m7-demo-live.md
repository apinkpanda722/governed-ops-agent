날짜: 2026-10-22. 이 문서는 mock 시뮬레이션 데모의 리허설과 본촬영 결과다. **평가가 아니며 공식 수치를 만들거나 바꾸지 않는다.** 실제 Jira·Slack 발송이나 실서비스 롤아웃을 검증한 것도 아니다. 영상: [프로젝트 B 시연(8분 14초, 유튜브 일부 공개)](https://youtu.be/Ke_b9BqbHR4), [프로젝트 A 시연(2분 41초)](https://youtu.be/F-HQYN8eit8). 영상의 모든 계정은 데모 계정이다.

출처 표기: **사용자 보고**는 사용자가 live 환경에서 실행·관찰한 값을 어드바이저 세션을 거쳐 전달받은 것이고 이 세션이 로그·DB와 대조하지 않았다. **이 세션**은 이 세션이 직접 실행한 것(`make verify`, CI, 문서 대조)이다. 기록 번호(#n)는 감사 체인의 레코드 번호다. 수치는 보고된 값을 그대로 옮겼고 새로 계산하지 않았다.

## 2. 실행 환경과 고정점

- 구성은 [DEMO.md 사전 준비](../DEMO.md#사전-준비사용자-실행)를 따랐다: live A MCP(8765), mock-jira·mock-slack(compose), LiteLLM, 호스트 `make serve`, 웹 `next start`(3100), 프로필 `writes_team`, v2 Guardrail off(공식 구성 v1), 데모 로그인, Langfuse obs 스택. 실제 설정값은 이 세션이 확인하지 못했다(`.env`를 열지 않는다).
- 시연 호출은 비용 원장에 남는다. 원장 증분(`data/manifest/costs.jsonl`)은 이 결과 커밋에 함께 넣었다(원장만 올리는 PR 금지 규칙).
- 감사 체인 고정점(모두 `data/interim/audit` 체인, 레이블 중복이 가능하므로 **레이블이 아니라 seq로 구분**한다):

| 고정점 | seq | 시점 |
|---|---|---|
| `m7-demo-pre` (이전) | 1705 | 2026-10-16 |
| `m7-rehearsal-pre` | 1916 | 리허설, 2026-10-22 |
| `m7-demo-pre` | 1923 | 본촬영 직전 |
| `m7-demo-post` | 2014 | 2026-10-22T06:18:28Z |

  네 줄은 이 PR이 대기 파일에서 `docs/results/audit-anchors.jsonl`로 옮겨 커밋한다(ADR-012). 같은 대기 파일의 M8 회귀 실행 고정점 40줄(경로가 `data/results/dev/…` 아래의 untracked 복사본을 가리킨다)은 **옮기지 않았다**(§5.1).
- 화면의 고정점 수는 체인 폴더 기준이고 CLI `anchors_checked`는 저장소 전체 기준이다. 둘을 같은 수로 설명하지 않는다.
- 데모는 `data/results/`의 공식 결과·사전 등록 파일을 만들거나 고치지 않았다(이 문서와 고정점 이관은 예외).

### 3.6 Langfuse와 감사 시연

- **Langfuse**: trace 이름이 task ID(감사·mock 메타데이터의 `govops_task`와 같음). 영상에는 읽기 질의 R2의 trace(14:16:36)를 썼다. trace 맨 위 Input은 비어 있다(요청 원문은 M4 step 5 정책으로 일부러 넣지 않는다). 최종 답변은 마스킹 후 Output에 올라가고 승인 대기로 끝난 trace는 Output이 undefined다. 모델 호출 항목의 원문은 LiteLLM `turn_off_message_logging`으로 `redacted-by-litellm` 자리 표시자다.
- **`make demo-scene5`(영상 미사용)**: 처음엔 최신 고정점이 이전 날짜 체인에 있어 오늘 파일이 통째로 지워졌는데도(PASS 880→788) `tail_truncated`가 나오지 않고 스크립트가 exit 1로 끝났다. 오늘 체인 안에 새 고정점(seq 1916)을 남긴 뒤 PASS 881 → FAIL `tail_truncated seq=1916`으로 기대대로 동작했고, 본촬영 직전 고정점(seq 1923) 뒤 PASS 978 → FAIL `tail_truncated seq=1923`이었다. 따라서 **탐지는 오늘 체인에 새 고정점이 있을 때만 성립한다.** 이 시연은 영상에서 뺐으므로 영상 입증 항목이 아니다.

## 4. 운영 사고

1. **고정점 경로 깨짐(리허설).** M8 회귀 실행 두 건(`M8-CAND`·`M8-CTRL`)의 결과를 `data/interim/m8-regress/`로 옮기면서, 대기 파일의 고정점 40개(실행당 20시도)가 옛 경로를 가리켜 웹 기록 화면이 FAIL(`anchor_dir_missing` 40)이었다. 사용자가 각 이동본의 `attempts` 트리만 원래 경로로 `cp -R` 복사해 복구했고(`.git/info/exclude`로 커밋 차단), `make audit-verify`가 PASS했다. 복사본은 untracked이며 **이 PR에 포함하지 않고 머지 전까지 지우지 않는다.** 고정점 파일은 수정하지 않았다(서명 대상). 재발 방지 문구는 DEMO.md 사전 준비와 [M8 회귀 결과](2026-10-21-m8-metrics-regress-live.md)에 넣었다.
2. **서버 이중 기동.** `make serve`를 Ctrl+Z로 정지(STAT T)만 시켜 이전 프로세스 2개가 남았고 새 서버가 시작 단계에서 멈췄다. kill 뒤 해결. DEMO.md에 “내릴 때는 Ctrl+C, 멈추면 `ps` 확인 후 kill”을 넣었다.
3. **이상 응답 1건(장면 2 첫 시도, 2026-10-22 13:26 KST, `demo-finance-g3`).** 기록 #1950 모델 호출 → #1951 도구 호출(ID 조회, 결과 수 0) → #1952 모델 호출만 있고 승인·발송 이벤트는 없다(부작용 없음). 앞부분은 정상(찾을 수 없음, 허용 채널은 `team-finance`·`announce`뿐)이었으나 뒤에 외국어 단어와 영어 조각이 섞였다. 같은 문장의 재시도(13:30)는 정상이었다. 리허설 3회·장면 1 본촬영·재촬영은 정상이어서 촬영 중 1회 발생했다. **원인은 확인하지 못했다.** 영향은 응답 문구 품질이며 권한·발송 경계는 지켜졌다(§5의 한계 항목). 이상 문구는 인용하지 않는다.
4. **어드바이저 진단 철회(trace Input).** 어드바이저가 “trace Input이 null인 것은 정책과 구현의 어긋난 결함”이라 진단했으나, 커밋 `83d88df`(M4 step 5)가 `input.request`를 **의도적으로** 뺀 것이었고 `tests/test_obs_instrument.py:54`가 현재 동작을 단언한다. 사용자가 코드 유지로 결정했고 진단은 철회됐다. 이 오진은 `infra/litellm/config.obs.yaml` 주석(“요청·답변은 에이전트 span이 … 보낸다”)이 요청 부분을 잘못 적은 데서 비롯된 것으로 보인다(주석 정정은 후속 PR).
5. **본촬영 전 승인된 시도 1건.** announce 메시지가 2건(`message-2`, `message-3`)이 되었다. 촬영 대상은 `message-3`이다. mock 상태이므로 부작용 범위는 mock-slack 안이다.

## 5. 설계 판단과 한계

이번 판의 **한계 항목**이다(후속 확인 항목이 아니다).

1. **복사본 의존.** `make audit-verify`와 기록 화면 PASS는 M8 회귀 결과의 untracked 복사본이 원위치에 있어야 한다. 새 클론에서는 대기 파일의 M8 줄이 없으므로 영향이 없지만, 이 호스트에서는 복사본을 지우면 `anchor_dir_missing`이 다시 난다. 또한 **M8 회귀 고정점 40개는 로컬 대기 파일에만 있고 커밋하지 않았다**(결과 폴더가 untracked이고, 커밋하면 새 체크아웃의 `audit-verify`가 `anchor_dir_missing`이 된다).
2. **이상 응답.** 최종 응답의 언어·형식 검사가 현재 있는지는 확인하지 않았다(있다/없다로 단정하지 않는다). 원인 미확정이며 같은 현상이 다시 생길 수 있다.
3. **trace에 원문이 없다.** 요청 원문과 프롬프트 원문은 trace에 남기지 않아 trace만으로 프롬프트를 재현하기 어렵다(개인정보 보호와 맞바꾼 것이며 디버깅이 불편하다). **환경별 원문 기록 스위치는 현재 없다.** 마스킹은 정규식 기반이라 이름·자유 서술 속 개인정보는 가리지 못한다.
4. **V15 근거 범위.** 검색 반환 전체를 근거로 평가해 정상 요청을 막는 한계(4a)는 그대로다. 영상의 4b가 통과한 것은 문서 ID를 지정해 근거를 한 건으로 한정했기 때문이다.
5. **영상으로 입증하지 않는 것.** 응답 유실 뒤 정확히 한 번 발송(장애 주입)과 꼬리 절단 탐지(`demo-scene5`)는 영상에 없다. 근거는 각각 M3·M4 결과와 리허설 확인이다.
6. **mock 시뮬레이션.** 실제 Jira·Slack, 실서비스 롤아웃, 다른 사용자 규모의 검증이 아니다. 이 시연은 평가가 아니며 공식 수치를 만들거나 바꾸지 않는다. 영상의 8분 14초는 설계의 약 3분 30초 구성과 다르다.
