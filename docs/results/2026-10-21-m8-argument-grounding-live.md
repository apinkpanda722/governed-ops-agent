## 3. 결과

분모를 함께 쓴다. 합계는 참고로만 쓰고 읽기·쓰기를 나눠 읽는다.

| 대상 | 읽기 근거율 | 쓰기 근거율 | 합계 근거율(참고) | 읽기 근거 없는 호출 | 쓰기 근거 없는 호출 | 합계 근거 없는 호출(참고) |
|---|---|---|---|---|---|---|
| 공식 N2 (120 실행) | 153/153 | 114/114 | 267/267 | 0/150 | 0/59 | 0/209 |
| 참고 N1a (`6b3ec0b1…`) | 34/34 | 24/24 | 58/58 | 0/34 | 0/10 | 0/44 |
| 참고 N1b (`6dba4af2…`) | 32/32 | 23/23 | 55/55 | 0/32 | 0/10 | 0/42 |

근거율은 `grounded ID / 인자 ID 전체`, 근거 없는 호출 비율은 `ungrounded ID가 하나라도 있는 호출 / ID를 담은 호출`이다. ID는 호출 안에서 고유하게 센다.

쓰기를 관측 `ok` 값별로 나눈 근거율:

| 대상 | 쓰기 `ok=true` | 쓰기 `ok=false` | 쓰기 `ok` 미상 |
|---|---|---|---|
| 공식 N2 | 114/114 | 0/0 | 0/0 |
| 참고 N1a | 24/24 | 0/0 | 0/0 |
| 참고 N1b | 23/23 | 0/0 | 0/0 |

`ok=false`·미상 쓰기가 없어 해당 칸은 분모 0(`0/0`)이다. 이 데이터에서는 인자 검증에서 거절된 쓰기 초안이 없었다(① 결과의 쓰기 초안 `ok` 78/78과 일치한다).

### 3-1. 정합성

- 공식 N2의 호출 293 = ID를 담은 호출 209 + ID 없는 호출 84다. 관측 호출 293은 ① 도구 호출 보고서(읽기 215 + 쓰기 초안 78)의 분모와 일치한다. N1a·N1b의 52도 ① 보고서의 합계 ok 분모(52)와 같다.
- 관측 호출 = assistant 호출(차이 0)은 **그래프 단계에서 거절된 읽기가 0건**이었다는 뜻이다. ① 결과 문서에서 적은 비대칭(거절된 읽기는 관측에 없고 assistant 호출에는 있음)이 이번 데이터에서는 실제로 생기지 않았다. 0건은 관측값이며 그래프에서 읽기가 거절될 수 없다는 증명이 아니다.
- 연결 없음·체크포인트 없음·호출 없는 행·다중 thread가 모두 0이라 160행이 전부 하나의 thread에서 호출을 읽혔다. 인자 JSON 파싱 실패와 쓰기 `ok` 미상도 0이다.
- 최상위 집계는 `rows.jsonl`과 같은 입력에서 계산하며(테스트가 일치를 검사한다) 보고서에는 인자 원문이 없다.

## 4. 100%를 읽는 법

- 267/267과 0/209는 **관측값**이다. 인자 ID가 호출 이전 근거에 모두 있었다는 사실이며, 호출 인자가 정확하다는 뜻이 아니다.
- 지표가 공허하지 않다는 근거: 근거에 없는 ID를 잡아내는 로직은 합성 입력으로 검증돼 있다. `test_ids_are_grounded_by_request_and_earlier_tool_messages_only`는 요청 문장과 앞선 tool 메시지에 있는 ID만 grounded이고 이후 결과에만 나오는 ID는 ungrounded로 센다는 것을, `test_same_turn_results_do_not_ground_parallel_calls`는 같은 턴의 결과가 같은 턴의 병렬 호출을 근거 짓지 못함을 검사한다. 분모 0 처리와 ID가 없는 호출·파싱 실패 구분도 별도 테스트가 있다.
- 호출 중 84개(공식 N2)는 ID를 담지 않아 근거율의 분모에 들어가지 않는다(그 호출들의 인자 내용은 열람하지 않았다). 근거율은 ID가 있는 209개 호출의 ID 267개에 대한 값이다.

## 5. 한계

- **정답 인자 대조가 아니다.** 평가 명세에 정답 인자나 정답 호출 궤적이 없어 Ragas ToolCallAccuracy 식 대조를 하지 않았다. 근거에 있는 다른 ID를 잘못 골라도 grounded로 센다.
- 자유 텍스트 인자(검색어·메시지 본문)의 의미는 평가하지 않는다. ID 패턴(`INC-YYYY-NNN`, `syn-*-NNN`, 티켓 키)에 맞지 않는 식별자는 보지 않는다.
- 근거는 요청 문장과 앞선 tool 메시지뿐이다. 평가 task는 단일 turn이라 이전 turn 근거는 없다. tool 결과가 `…(잘림)`으로 잘렸다면 잘린 부분의 ID는 근거로 잡히지 않는다.
- 쓰기 `ok`는 제출 초안의 tool 응답에 `error` 키가 없다는 뜻이며 실행 성공이 아니다. 정책·범위 검사에서 막힌 초안도 `ok=true`다(① 결과 §2-1).
- 대상은 기준 모델 `gpt-6-luna` 실행뿐이고 1회씩이다. 실행 간 노이즈를 모른다.
- 결과 파일이 `data/interim/`에 있어 PR에는 요약 수치와 sha256만 남는다.

## 6. 주장하지 않는 것

- 인자 정확도가 100%라는 것. 이 지표는 정답 대조가 아니다.
- "도구 선택 정확도"나 도구 호출이 옳았다는 것. 호출 여부·이름은 ① 도구 호출 지표의 몫이고 그것도 정확도가 아니다.
- 다른 모델·다른 task 세트·다른 프롬프트로의 일반화. 후보(Sonnet) 실행의 인자 근거율은 측정하지 않았다.
- 인자 ID가 근거에 있다는 것이 그 ID를 호출에 쓰는 것이 옳았다는 뜻이라는 것.
- 통계적 유의성, 공식 M6 수치의 변경.
