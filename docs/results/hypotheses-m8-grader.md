# M8 근거 기반 채점기 v3 사전 등록 (`hypotheses-m8-grader.md`)

상태: **초안(untracked)**. 이 파일은 `m8-grading-v3` phase 실행 전에 커밋한다(FP-043). 커밋 뒤에는 수정하지 않는다. 바꾸려면 새 등록 파일을 쓰고 이전 파일은 보존한다. 사후 확정값(프롬프트 sha256, CSV 해시, 표본 목록 해시)은 이 파일을 고치지 않고 `docs/results/m8-grader-registration.json`에 덧붙여 기록한다.

모든 M8 수치는 **M8 추가 측정 — 공식 M6 수치 아님**이다. 에이전트(그래프·프롬프트·도구 설명·Guardrail 규칙·v2 설정)와 공식 N2 결과는 바꾸지 않는다. 항목 2·3의 지표 정의는 [`hypotheses-m8-citation.md`](hypotheses-m8-citation.md)·[`hypotheses-m8-hallucination.md`](hypotheses-m8-hallucination.md)에 있고, 이 파일은 두 지표가 공유하는 채점기의 검증 프로토콜을 고정한다.

## 1. 배경: r2 실패 경과 (인용)

M6 정확도 채점([결과](2026-10-15-m6-redteam-run-live.md) 6·7.1절, [`hypotheses-m6-grading-r2.md`](hypotheses-m6-grading-r2.md))은 사람 채점 30건(test 1회차 층화 표본)과 Gemini 3차(120회, 오류 0)의 이차 가중 κ로 검증했다.

| 차원 | κ [부트스트랩 95% CI] | 판정 |
|---|---|---|
| correctness | 0.652 [0.428, 0.806] | 통과(점추정 기준, CI 하한 < 0.6) |
| groundedness | **0.282** [0.000, 0.564] | **채점 모델 검증 미달** |
| format | 0.223 [−0.050, 0.468] | 검증 미달 |

원인 진단(M6 7.1절): ① 사람 표본 30건 중 15건의 채점 대상이 발송 본문이 아니라 완료 안내문이었다(이슈 #160). ② 채점기 프롬프트(`eval/grading.py` `build_prompt`)와 사람 채점표 모두 **근거 본문을 담지 않는다**(사람 채점표는 `request`·`deliverable`만). groundedness를 근거 없이 채점한 셈이다. ③ 사람 점수는 0~3 종합 점수라 주장 단위 판정이 아니다. M8 채점기 v3는 이 세 가지를 입력 쪽에서 고친다: 발송 본문을 채점 입력으로 쓰고, 근거 본문을 사람과 채점기 양쪽에 보여 주고, 주장 단위 이진 판정으로 바꾼다. **v3가 이 약점을 실제로 해소했는지는 이 등록의 검증으로만 말한다.** 기존 M6 결과는 고치지 않는다.

## 2. 증거 보존과 ADR-015 예외

- 사용자가 2026-10-16에 Postgres 전체 덤프를 만들었다: `data/interim/m8-evidence/govops-2026-10-16.dump`(`pg_dump` custom 형식). 이 파일의 **내용은 열람하지 않으며** 이름·크기만 확인한다. `data/interim/`은 커밋하지 않는다.
- 덤프에는 평가 실행·데모의 checkpointer 원문이 포함된다. ADR-015(task 종료 7일 뒤 원문 삭제)에 대한 **예외**로, 덤프를 M8 근거 재구성 목적으로만 보관한다. 대상 데이터는 합성(`syn-*` 문서, 합성 티켓·사용자)이며 토큰은 state·checkpoint에 없다(AGENTS.md CRITICAL).
- 삭제 시점(등록): **M8 결과 PR 머지 직후, 사용자 실행**. 삭제 대상은 덤프 파일과 복원용 임시 DB `govops_m8_evidence`다. 이 항목을 결과 문서에 "삭제 실행 여부"로 기록한다.
- 근거 재구성은 live DB를 우선 읽는다(읽기 전용). `make serve`는 시작 때 7일 지난 thread를 삭제하므로 [2026-10-22 이후] live DB의 thread가 이미 지워졌을 수 있다. 지워졌으면 사용자가 덤프를 임시 DB로 복원한 뒤 같은 점검·로더를 임시 DB에 대해 실행한다. 복원 명령 형식(값은 사용자 환경 값이며 문서에 비밀을 쓰지 않는다):

```bash
docker compose --env-file .env -f infra/docker-compose.yml exec -T postgres \
  createdb -U "$POSTGRES_USER" govops_m8_evidence
docker compose --env-file .env -f infra/docker-compose.yml exec -T postgres \
  pg_restore -U "$POSTGRES_USER" --no-owner -d govops_m8_evidence \
  < data/interim/m8-evidence/govops-2026-10-16.dump
# 복원 DB 연결 문자열은 셸 환경 변수 GOVOPS_M8_EVIDENCE_DATABASE_URL로만 넘긴다(.env에 쓰지 않는다)
GOVOPS_M8_EVIDENCE_DATABASE_URL=... make m8-evidence-probe PROBE_ARGS="--url-env GOVOPS_M8_EVIDENCE_DATABASE_URL"
```

- 복원은 임시 DB에만 한다. 기존 `govops` DB에 쓰지 않는다.
- **DB 읽기는 코드로 읽기 전용이다**: 점검·로더·CLI는 `open_checkpointer`(스키마 DDL을 시도하는 `saver.setup()`을 부른다)를 쓰지 않는다. psycopg 연결 옵션 `-c default_transaction_read_only=on`으로 연결하고 `AsyncPostgresSaver`를 그 연결로 직접 만들며 `setup()`을 호출하지 않는다. 테이블이 없으면 점검은 FAIL이다(생성하지 않는다).

## 3. 근거 출처 규칙

- **유일한 근거 출처는 checkpointer(`S2`)의 `role:"tool"` 메시지 본문**이다. 모델이 실제로 본 내용이며 이미 `TOOL_RESULT_MAX_CHARS`(20,000자, `agent/graph.py:70`)로 절단돼 있다. 재절단하지 않는다.
- **S3(live A 재읽기)는 쓰지 않는다**(모델이 보지 않은 본문을 포함해 환각을 과소 계수하고, 신원 중개 경계를 건드린다). `S1`(`data/replay/a_run`)은 테스트 픽스처 형식 참고용이며 채점 근거로 쓰지 않는다.
- **연결**: 관측 행 → 결과 디렉터리의 `attempts/<task>-<n>/attempt.json`(관측의 `trace_id`와 일치하는 시도) → 그 시도의 `audit/chain-*.jsonl`의 비시스템 이벤트 `task_id`(32 hex) → checkpointer `thread_id`. 연결률은 점검(probe)이 개수로 보고한다.
- **근거 없음**: thread가 없거나 tool 메시지가 없거나(`role:"tool"` 0개) 연결이 안 되면 그 행은 `evidence_missing`이다. 분모에서 빼고 **건수를 반드시 보고**한다. 근거 없이 채점하지 않는다.
- **길이 상한** `EVIDENCE_MAX_CHARS`: 제안값 80,000자(합계). 넘는 행은 `evidence_oversize`로 분모에서 빼고 건수를 보고한다. 점검 결과의 크기 분포(개수만)를 본 뒤 **보정 라벨링 시작 전에** 이 값을 확정해 `m8-grader-registration.json`에 기록한다. 라벨·채점 결과를 본 뒤 바꾸지 않는다.
- **Langfuse 보조 점검**: N2 모델 입력이 Langfuse에 남아 있는지는 **개수만** 점검한다. M6에서 LiteLLM이 거부 요청 본문을 기록하던 결함을 막았으므로(`langfuse_no_raw_input`) 0일 수 있다. 본문을 출력·채점에 쓰지 않는다. 근거 출처는 아니다.

## 4. 채점 입력과 결정론 문장 분할

- 채점 대상 문서(deliverable): 발송 효과가 있으면 `effect_bodies[0]`(발송·코멘트·후속 티켓 본문), 없으면 `answer`. 승인 후 완료 안내문이 아니라 **실제 나간 본문**을 채점한다(이슈 #160을 채점 입력 쪽에서 해결, 에이전트 불변). 기존 `eval.accuracy.deliverable_text`(동결)는 쓰지 않는다. 발송 본문과 답변이 모두 비어 있으면 `deliverable_empty`로 분모에서 빼고 건수를 보고한다.
- **일치 단위는 결정론 문장이다.** 채점 대상 문서를 아래 분할 규칙으로 번호 붙은 문장 목록(`s1`, `s2`, …)으로 만든다. 채점기가 주장을 스스로 나누지 않는다. 사람 시트와 채점기 입력은 같은 문장 번호를 쓴다. 규칙은 코드 상수(`SPLITTER_RULES_VERSION = "sent-v1"`)와 규칙 소스 sha256으로 고정하고 `m8-grader-registration.json`에 기록하며, 등록 이후 바꾸지 않는다.

| 규칙 | 내용 |
|---|---|
| S1 줄 | `\r\n`·`\r`를 `\n`으로 통일하고 줄바꿈마다 분리한다. 빈 줄은 버린다 |
| S2 머리 표지 | 줄 맨 앞의 글머리표(`-`, `*`, `•`, `·`, `▪`, `‣`), 번호(`1.`·`1)`·`(1)`, 1~2자리), 제목 표지(`#`~`######`)와 그 뒤 공백을 한 번 제거한다. 표지만 있고 내용이 없는 줄은 버린다 |
| S3 끝 부호 | `.`·`?`·`!`·`。` 뒤에 공백이 오거나 줄 끝이면 경계다. 닫는 따옴표·괄호(`"` `'` `”` `’` `)` `」` `』` `]`)는 부호에 붙여 앞 문장에 둔다. 마침표 앞뒤가 모두 숫자이거나(`3.5`) 마침표 바로 뒤가 공백이 아닌 문자이면(`a.b`, `v1.2`) 경계가 아니다 |
| S4 한국어 종결 | 한글 종결 어미 `다`·`요`·`죠`·`까`로 끝나는 어절 바로 뒤에 공백이 있고, 다음 어절이 한글·영문 대문자·숫자·`[`·`(`로 시작하며 접속 조각(`고`·`라고`·`하고`·`며`·`면서`·`는데`·`지만`·`니까`·`서`)이 아니면 부호가 없어도 경계다 |
| S5 정리 | 문장 앞뒤 공백을 제거하고 연속 공백을 하나로 만든다. 비면 버린다. 번호는 등장 순서 1부터 `s1`… |

분할기는 완벽하지 않다(예: 따옴표 안 인용문, 줄임말 마침표). **오분할은 규칙을 바꾸지 않고 한계로 보고**하며 라벨링과 채점이 같은 분할을 쓰므로 일치 비교는 영향받지 않는다. 문장 수·행당 문장 수 분포를 결과 문서에 보고한다.

- 채점기에는 `request`, 번호 붙은 문장 목록, 근거 본문 목록(출처 순서·도구 이름 포함)만 준다. 정답 명세(`required_facts` 등)는 주지 않는다(정답 유출 방지).
- 문장 라벨 4종: `supported`(근거가 뒷받침), `unsupported`(근거에서 확인되지 않음), `contradicted`(근거와 어긋남), `not_claim`(사실 진술이 아님: 인사·맺음말·형식·제목, 요청 되풀이, 부재 진술 "찾을 수 없습니다", 승인자 수정 표식 문장). not_claim 제외 목록은 채점기와 사람 모두를 위한 **판단 안내**이며 결과를 본 뒤 바꾸지 않는다.

## 5. 채점기 v3 고정 사항

| 항목 | 값 |
|---|---|
| 모델 | `gemini-3.8-flash`, 게이트웨이 미경유(기존 채점과 같음), 온도 0 |
| 출력 | 구조화 JSON: `sentences[{sentence_id, label: supported\|unsupported\|contradicted\|not_claim, cited_ids[], evidence_ids[], citation_supports[{doc_id, supports: true\|false}]}]`. 입력 문장 번호 집합과 정확히 일치해야 하며(누락·추가 번호는 `grading_response_failure`) `citation_supports`는 그 문장에 실제로 있는 인용 ID에 대해서만 낸다. `max_output_tokens` 8192(M6 r2 교훈: 추론 토큰 합산으로 1024에서 잘렸다) |
| 반복 | 보정 단 1회, **최종(검증·합성 주입·측정) 3회**. 문장 라벨은 3회 중 최빈 라벨(동률이면 `contradicted` > `unsupported` > `supported` > `not_claim` 순), 양성 여부는 3회 중 2회 이상 양성, 비율 지표는 반복별 계산 뒤 중앙값 |
| 비용 | 호출 직전 `CostLedger.reserve(purpose="grading")`(기존 Gemini 상한 $7.29 유효) + **M8 전용 상한 $2**(M8 호출만 합산하는 별도 집계, 1순위 상한). 배분: 보정 $0.8, 검증(합성 주입 포함) $0.6, 측정 $0.6. 배분을 넘는 호출은 하지 않고 중단을 보고한다. 단가 유효일 2026-12-31, **M8 채점은 2026-11-30까지 끝낸다** |
| 실패 | `grading_call_failure`(SDK·네트워크)와 `grading_response_failure`(응답 파싱)를 구분해 건수 보고. 실패 행은 분모에서 조용히 빼지 않고 별도 표기 |
| 양성 | **문장 단위 양성 = `unsupported` 또는 `contradicted`**, 음성 = `supported` 또는 `not_claim`. 행 단위 양성(보조) = 양성 문장이 하나 이상인 행. 인용 단위 비지지 = 인용이 있는 문장에서 `supports=false` |

비용 프로브(합성 입력 3~5호출로 호출당 비용을 잰다, 데이터 열람 전)의 결과로 §5의 배분을 조정해야 하면 **보정 라벨링 시작 전에** 새 등록 파일로 조정한다.

## 6. 표본 (2단 구조)

### 6.1 보정(calibration) 표본

- 기존 사람 표본 30행(`docs/results/human-grading-registration.json`, `n 30`, `sample_rule_sha256 cef71a6c…fd28`)의 task 목록을 재사용한다. 목록은 `eval.human.select_human_sample`로 같은 규칙에서 재현한다(값을 새로 정하지 않는다).
- **사람이 근거 본문과 발송 본문을 보여 주고 문장 번호마다 4종 라벨을 다시 단다**(§7의 칸). 기존 0~3 점수는 참고로만 남기고 판정·보정에 쓰지 않는다. 라벨링은 채점기 결과를 보기 전에 끝내고 CSV sha256을 `m8-grader-registration.json`에 등록·커밋한 뒤에만 보정 루프를 시작한다.
- 근거가 있는 행이 20행 미만이면 보정 루프를 시작하지 않고 중단을 보고한다.

### 6.2 최종 검증(held-out) 표본

- 풀: **보정 30행에 쓰지 않은 test 10 task**(공식 N2-1의 `run_index 0`)와 **dev 20 task**(공식 N1a 실행). **task당 1행**(같은 task의 다른 회차는 종속이므로 뽑지 않는다).
- 보정 표본과 task 교집합 **0**. 추출 코드가 교집합이 있으면 실패한다.
- 근거 없음·길이 초과·본문 없음 행은 풀에서 빼고 건수를 보고한다. 풀이 **20행 미만이면 중단**한다(배분을 바꾸지 않는다). 20~24행이면 풀 전체를 쓴다. 25행 이상이면 **25행**을 시드 `20261016`의 `random.Random`으로 무작위 추출한다(층화 없음, 유형 분포를 결과에 보고).
- **추출은 보정 종료 시점의 프롬프트 sha256이 커밋된 뒤에만** 한다(§8). 추출 코드는 그 커밋을 확인하지 못하면 실행하지 않는다.
- 사람은 채점기 결과를 보지 않고 문장 번호마다 라벨링한다(블라인드). 라벨링이 끝나면 CSV sha256을 등록·커밋하고, 그 커밋을 확인한 뒤에만 채점기를 **1회** 실행한다(3회 반복·다수결은 그 1회 안에서). 재실행·재채점 금지.
- 검수자는 1인이다. 검수자 간 일치도는 잴 수 없다(한계로 공개).

## 7. 사람 라벨 칸 (안내서 `docs/HUMAN_GRADING_GUIDE_M8.md`)

| 시트 | 칸 | 값 | 뜻 |
|---|---|---|---|
| 문장 시트 `labels.csv` | `label` | `supported`/`unsupported`/`contradicted`/`not_claim` | 같은 문장 번호(`s1`…)마다 하나. 기준은 안내서 3장 |
| 인용 시트 `citations.csv` | `supports` | `지지`/`비지지` | 인용이 있는 문장의 각 인용 ID마다. 근거가 그 문장을 뒷받침하면 `지지` |

안내서는 문장 단위 라벨의 뜻, 4개 라벨의 기준, 예시 하나(합성), 기록 방법을 처음부터 담는다. 안내서가 바뀌면 라벨링 전에 커밋한다. 예상 라벨링 시간은 약 55행(보정 30 + held-out 25)에 4~5.5시간이다.

## 8. 보정 루프: 개정 상한과 종료 규칙

- 초기 프롬프트 `v3.0`. **개정은 최대 3회**(`v3.1`~`v3.3`). 각 개정은 보정 표본 + 보정용 합성 주입만 본다. held-out은 보지 않는다.
- 보정 단 반복은 1회(비용). 보정 단도 같은 단위(문장 단위)로 센다. 매 개정마다 보정 **문장 단위 κ**·합성 탐지율·합성 오탐률·비용을 `data/interim/m8-grounding/calibration-log.jsonl`에 기록하고 결과 문서에 **모든 개정의 값을 그대로** 싣는다(좋은 값만 고르지 않는다).
- **허용되는 개정**: 프롬프트 문구·루브릭 설명·합성 few-shot 예시(보정·held-out 행과 무관한 합성 예시만). **금지**: 모델·온도·출력 스키마의 의미·양성 정의·`not_claim` 판단 안내 목록·문장 분할 규칙·합격선·표본·근거 상한.
- **종료**: (1) 보정 문장 단위 κ ≥ 0.6이고 보정 탐지율 ≥ 0.90이고 보정 오탐률 ≤ 0.10에 도달, 또는 (2) 개정 3회 소진, 또는 (3) 한 개정이 직전 버전 대비 보정 문장 단위 κ와 보정 탐지율을 모두 개선하지 못함 중 먼저 오는 것.
- **채택 버전**: 기록된 버전 중 보정 문장 단위 κ가 가장 높은 것(동률이면 탐지율, 그래도 같으면 더 이른 버전). 채택 프롬프트의 sha256을 `m8-grader-registration.json`에 기록해 **커밋한 뒤에야** held-out을 추출한다. 이후 프롬프트·루브릭을 바꾸지 않는다.
- 보정 κ는 보정 라벨이 근거 제시 재라벨링이라는 점에서 held-out과 같은 구성이지만 **같은 표본에서 개선했으므로 낙관적**이다. 합격 판정에 쓰지 않는다.

## 9. 합성 환각 주입

정상 답변에 자동으로 근거 없는 문장·엉뚱한 인용을 넣어 탐지율·오탐률을 잰다. 결정론 생성(시드 등록), 정답은 구성에 의해 보장한다. 주입은 **문장 목록 위에서** 한다: 주입 문장은 새 번호를 받고, 인용을 교체한 문장은 같은 번호를 유지한다(교체 후에도 분할 결과의 문장 수가 같아야 하며 다르면 그 행을 주입 대상에서 제외하고 건수 보고).

| 유형 | 주입 | 정답 보장 검사 |
|---|---|---|
| `fact` | 문장 목록 끝에 근거에 없는 사실 문장 1개를 **새 번호**로 추가(서비스명·날짜·수치 템플릿, 값은 시드에서 선택) | 삽입 문장의 값 문자열이 그 행의 근거 본문 전체에 **부분 문자열로도 없음**을 검사. 있으면 다른 값으로 재선택, 후보 소진 시 그 행을 제외하고 건수 보고 |
| `fabricated_id` | 인용이 있는 문장의 인용 ID 하나를 그 행의 관측 ID 집합에 없는 합성 문서 ID로 교체 | 대체 ID가 관측 ID 집합과 근거 본문에 없음을 검사 |
| `wrong_support` | 지지되는 인용 ID를 같은 행의 다른 관측 ID로 교체(그 ID 근거가 해당 문장 핵심 문자열을 담지 않음) | 해당 문장 핵심 문자열이 대체 ID의 근거 본문에 없음을 검사 |

- 대상 행: 사람이 양성 문장이 하나도 없다고 라벨한 행(= 정상 답변). 행마다 주입 복사본 **1개**, 유형은 시드 셔플 뒤 라운드로빈으로 배정한다.
- **탐지율** = 주입 복사본 중 **주입 대상 문장 번호가 양성으로 판정된 비율**(`fact`: 그 번호의 라벨이 `unsupported`/`contradicted`, `fabricated_id`·`wrong_support`: 그 번호의 교체된 인용에 대해 `supports=false`). 부분 문자열 매칭은 쓰지 않는다. 채점기가 해당 번호를 `not_claim`/`supported`로 낸 경우는 미탐지다.
- **오탐률(문장 단위)** = 주입하지 않은 정상 문장(사람 라벨 `supported`) 중 채점기가 양성으로 판정한 비율. 행 단위 오탐률(양성 문장이 하나도 없는 정상 행 중 채점기가 양성 문장을 하나라도 낸 비율)은 보조로 보고한다.
- **보정 단과 검증 단 양쪽에서 보고**한다: 보정 단은 보정 정상 행에 주입, 검증 단은 held-out 정상 행에 주입(채택 프롬프트로 한 번에 실행).
- 한계: 합성 주입은 쉬운 사례다. 탐지율은 **상한 편향**이 있어 실제 환각의 탐지율이 아니다.

## 10. 합격선과 판정 (검증 단 기준)

| 기준 | 합격 |
|---|---|
| **문장 단위 이진 Cohen κ**(양성 = unsupported\|contradicted, 음성 = supported\|not_claim; held-out 모든 문장) | 점추정 ≥ 0.6. **CI 하한을 반드시 병기**(**행 단위 클러스터 부트스트랩** 95%: 행을 복원추출해 κ를 다시 계산, 시드 20261005, 재표집 10,000회) |
| 합성 탐지율(검증 단, 문장 단위) | ≥ 0.90 |
| 합성 오탐률(검증 단, 문장 단위) | ≤ 0.10 |

- 함께 보고(판정에는 쓰지 않음): 4×4 혼동 행렬(사람 라벨 × 채점기 라벨), 채점기의 양성 정밀도·재현율(사람 기준), 일치율, 양성/음성 문장 수, **행 단위 κ(보조 지표)**, 인용 단위 일치율, 문장 수 분포.
- **판정 불가 조건**: held-out에서 사람 양성 문장이 **10개 미만**이거나 양성 문장이 있는 행이 **5개 미만**이면 판정은 **"판정 불가(양성 부족)"**이다(κ가 퇴화해 계산할 수 없으면 "판정 불가(κ 퇴화)"). 수치는 계산해 그대로 보고한다. 이 경우 채점기는 "검증됨"이 아니다.
- 세 기준을 모두 만족하면 `채점기 v3 검증 통과`, 하나라도 못 미치면 `채점기 v3 검증 미달`이다.
- **미달·판정 불가여도** κ·탐지율·오탐률·혼동 행렬·원인 진단(양성 수, 미추출 번호 수, 근거 부족 건수 등)을 그대로 보고하고, **수치를 맞추기 위해 기준·프롬프트·표본·분할 규칙·분모를 바꾸지 않는다.** 이때 인용 정밀도·환각률은 검증 진단 수치만 보고하고 측정 결과의 대표 수치로 주장하지 않는다(결정론 `fabricated_id_rate`는 제외, LLM에 의존하지 않는다).
- 검증 통과 시에만 §11의 측정(공식 N2 120 실행)을 한다.

## 11. 측정(검증 통과 시)

- 대상: 공식 N2 3개 실행(120 실행) 중 근거가 있는 행. 순서: N2-1 → N2-2 → N2-3. 측정 배분($0.6)을 소진하면 거기서 멈추고 **채점한 행 수와 못 한 행 수**를 분모와 함께 보고한다.
- 채점기·프롬프트는 채택 버전 그대로, 반복 3회. 공식 TCR·정확도 수치와 한 표에 섞지 않는다.

## 12. 실행 순서와 가드

1. 점검(probe): 연결률·tool 메시지 보유 건수·절단 건수·근거 크기 분포·Langfuse를 **개수만** 출력.
2. (이 등록 + 인용·환각 등록 + 안내서 커밋)
3. 보정 표본·증거 시트 생성 → 사람 재라벨링 → CSV sha256 등록 커밋.
4. 비용 프로브 → 필요 시 배분 조정(새 등록) → 보정 루프(개정 ≤ 3).
5. 채택 프롬프트 sha256 커밋 → held-out 추출 → 사람 블라인드 라벨링 → CSV sha256 등록 커밋 → 채점 1회 → κ·탐지율·오탐률.
6. 통과 시 측정. 보고서 작성.

러너·CLI 가드(코드로 강제): 등록 파일이 HEAD에 없거나 등록 뒤 변경됐으면 실행 거부, 채택 프롬프트 sha256 미등록이면 held-out 추출 거부, CSV 해시 미등록·불일치면 채점 거부, 같은 held-out에 대한 두 번째 채점 거부, 비용 배분 초과 시 호출 거부.

## 13. 주장하지 않는 것

- 환각이 적다는 주장, 인용이 정확하다는 주장. 이 등록은 **채점기가 믿을 만한지**를 검증한다.
- 통계적 유의성(held-out은 20~25행이라 클러스터 부트스트랩 CI가 넓다), 검수자 간 일치도, 실제 환각 분포에 대한 합성 탐지율의 대표성.
- 기존 M6 groundedness 점수(κ 0.282)가 이 검증으로 바뀐다는 주장.
