## 한계

- 평가 경로는 in-process ASGI로 실제 API 코드를 거치지만 실제 서버 프로세스와 세션 TTL은 거치지 않는다.
- 비골든 task의 관측에는 도구 결과 본문 대신 구조 ID만 보관한다. 비골든 task의 `run_sql` SQL 문자열 같은 인자는 trace(`tool.args`)로만 확인할 수 있다.
- V15 검사는 문서 단위이고, ID가 없는 `run_sql` 결과(집계)는 검사 대상이 아니다. 검색 결과 발췌에 팀 전용 문서가 섞이면 공개 정답 문서가 있어도 전사 공지·공개 티켓 코멘트가 차단된다(오차단 2건으로 센다).
- 같은 요청에 대한 도구 선택은 실행 간 달라질 수 있다(T3-01). dev는 task당 1회만 실행하므로 이 변동은 TCR에 그대로 반영된다. test는 task당 3회라 pass^3으로 드러난다.
- 시작 시 정리는 체크포인트 전체 순회라 수백 건 규모를 전제한다. 정책 파일 해시 감사는 M4에서 추가한다.
- 설계 검토 중(2026-10-06) approvals 조회 문항 여부를 확인하다가 test T4 문항 6개(T4-02·03·04·05·07·08)의 요청 문장을 열람했다. 정답 값은 열람하지 않았고, 조직 정보 표와 프롬프트에는 이 열람 내용을 반영하지 않았다(표는 PR #51에서 열람 전에 확정).
